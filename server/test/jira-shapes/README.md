# Recorded Jira answers

The answers the fake Jira (`../fake-jira.ts`) is built from, and that `JIRA_SHAPES` in `server/src/jira/client.ts` must parse (`client.test.ts` checks every file).

They were written from Atlassian's REST documentation with Qualor's example values, not captured from a live site. Task 15's opt-in live check compares them with real answers.

Qualor calls REST v2 on both deployments: Cloud (`https://<name>.atlassian.net`, or the gateway `https://api.atlassian.com/ex/jira/<cloud id>`) and Data Center.

The behaviour the fake models comes from the same research: auth headers (https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/ , https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html), the CAPTCHA header `X-Seraph-LoginReason: AUTHENTICATION_DENIED` (https://developer.atlassian.com/server/jira/platform/basic-authentication/), and the limits and 429 headers (https://developer.atlassian.com/cloud/jira/platform/rate-limiting , https://confluence.atlassian.com/adminjiraserver110/adjusting-your-code-for-rate-limiting-1627461133.html).

## Not verified yet

- **The Data Center createmeta envelope.** The DC 11.3 OpenAPI shows a wrong schema for both createmeta answers; real answers are believed to carry the items under `values`, with `isLast`. The client reads `issueTypes`, `fields` or `values`. Unverified until Task 15's live check against a Data Center.
- **The status fields** (`fields.status.name`, `fields.status.statusCategory.key` in `new`, `indeterminate`, `done`) come from general Jira knowledge, not from the spec text.
- **Data Center's `warningMessages`** for an unknown id under `validateQuery: "warn"` (the fake adds them) come from general Jira knowledge.
- The fake's own texts for a bulk of more than 50 and for a JQL it cannot read are not Jira's.
