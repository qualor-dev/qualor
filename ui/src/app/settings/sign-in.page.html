How Qualor keeps you from being locked out

  • API and CI tokens keep working whatever you choose here.
  • Limiting password sign-in needs at least one break-glass administrator who is an active instance administrator with a password, and at least one enabled single sign-on connection.
  • Everyone else signs in with single sign-on. Their password, if they have one, is kept and works again when you set password sign-in back to everyone.
  • While password sign-in is limited, the last break-glass administrator who can still use a password cannot be deactivated or lose the instance administrator role. Set password sign-in back to everyone first.
  • If the identity provider fails, set QUALOR_FORCE_PASSWORD_SIGN_IN=true and restart the server: everyone with a password can sign in with it until you remove the variable.
